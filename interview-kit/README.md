## 路线一：面试前 15 分钟

1. 读 `03` 的 30 秒版本；
2. 读 `07` 的 60～90 秒全链路版；
3. 读 `06` 的“高频十题速背”；
4. 确认简历最终使用的 2～3 条，只看 `05` 中对应的短开场和边界防守；
5. 记住：已实现、Mock、真实联合样本、待平台验收和生产可用不能混用。

目标不是临时记更多，而是第一分钟讲得清楚，追问时不越界。

## 路线二：准备 1 小时

1. 用 10 分钟读 `01` 的三张图；
2. 用 15 分钟读 `07` 的主链、治理链、恢复链和架构时间线；
3. 用 15 分钟复习 `02` 的前四个亮点；
4. 用 10 分钟读 `06` 中与你薄弱点对应的五题；
5. 用 10 分钟朗读最终简历条目的完整脚本。

建议录音检查：有没有先说业务问题，能否解释为何不用开放式 ReAct、自由 SQL、盲目重试和原始日志直喂模型。

## 路线三：Agent 岗位专项

1. 横向读 `06`：先独立回答原八股，再看项目映射；
2. 纵向读 `07`：把组件复述成“上一阶段的问题怎样逼出下一层”；
3. 回到 `02`：为固定 Graph、Evidence-first、Checkpoint 和评测各准备一次方案对比；
4. 用 `05` 练追问，并把书面句子改成自己的表达。

这条路线解决“会讲项目但不会八股”和“会背八股但落不到工程”两个问题。

## 路线四：完整学习

1. 按 `01 → 07 → 02 → 06` 建立架构、演进、亮点和通用知识；
2. 沿源码链接走一遍 Intake、Worker、Graph、Gateway、SLS、Summary 和 Delivery；
3. 从 `04` 选择主线版或 Go 工程版组合，不要把七条全部放进简历；
4. 朗读 `03` 的 5 分钟稿，再练 `05` 对应的所有追问；
5. 最后删除任何自己无法解释、复现或证明的第一人称表述。

## 推荐的校招选择

投递 Agent 开发岗位，优先选择：

- 基于 Go/Eino 实现可审计日志排障 Agent；
- 构建 SLS 查询治理网关，默认拒绝越权调用；
- 建立 Evidence 约束，拦截 LLM 无依据摘要。

版面只能放两条时，保留第一条和第三条；岗位偏 Go 后端时，可换成“设计租约与 Checkpoint，支持任务故障恢复”。具体措辞和适用前提以 `04` 为准。

## 阅读约定与事实边界

源码链接基于 commit `e115d4dcd7993b1c25e0001be951dad2c2cc1f1c`。行号漂移时，优先按文件名和职责定位。

- Go 主链、Eino 固定图、SQLite 状态、查询治理、SLS CLI、方舟摘要和离线评测已实现；
- 飞书接收、卡片动作、Reply/Patch 与可靠投递功能已实现，真实平台验收待权限；
- 真实 SLS 与真实方舟已通过本地 Web 串入同一次单主 Logstore、count-only 调查；
- SQLite 仍是单实例技术预览；8 库时间线、真实 Metrics/Trace、企业 Runbook 和自动变更尚未完成；
- 项目只给证据和建议，不自动执行重启、回滚或修复。

不要虚构生产 QPS、准确率、节省时长、故障恢复次数或个人独立上线经历；不属于你且不能复现的内容，不要用第一人称认领。
