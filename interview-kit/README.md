# Log Agent 校招 Agent 开发面试材料

这套材料用于把 `D:\日志agent` 包装成一段真实、可验证、能经受追问的校招项目经历。
它不是产品宣传稿，也不建议逐字背完。
正确用法是先理解架构，再从七条简历候选中选择与你实际贡献一致的 2～3 条，最后练习对应口述稿。

## 阅读路线一：面试前 15 分钟

适合马上要面试，只需要恢复表达状态。

1. 先读项目介绍中的“30 秒版本”；
2. 打开简历候选，确认自己最终使用的是哪 2～3 条；
3. 只看这些条目对应的“20～30 秒开场”和“边界防守”；
4. 记住统一口径：已实现、已测试、真实联合验收、待平台验收不能混用。

目标不是临时记更多细节，
而是保证第一分钟讲得清楚，追问时不越过事实边界。

## 阅读路线二：准备 1 小时

适合当天系统复习一次。

1. 用 15 分钟读完项目架构中的三张图；
2. 用 15 分钟复习亮点一、二、三、四；
3. 用 10 分钟选择最终简历组合；
4. 用 20 分钟朗读对应的 2～3 分钟脚本和追问。

建议录音一次。
听完检查自己是否先说业务问题，
是否解释了为什么不用开放式 ReAct、直接 SDK、盲目重试或原始日志喂模型。

## 阅读路线三：完整学习

适合第一次建立项目认知或准备深挖面。

1. 完整阅读项目架构，并按源码链接走一遍调查主链；
2. 阅读七个亮点，给每个主题总结“问题—方案—效果—取舍”；
3. 从简历候选中确定主线版或 Go 工程版组合；
4. 朗读 5 分钟项目介绍，确保能脱离文档表达；
5. 逐条练习 28 个追问，并把回答改成自己的语言；
6. 最后对照事实边界，删除任何自己无法证明或解释的表述。

## 推荐的校招选择

投递 Agent 开发岗位，优先选择：

- 基于Go/Eino实现可审计日志排障Agent；
- 构建SLS查询治理网关，默认拒绝越权调用；
- 建立Evidence约束，拦截LLM无依据摘要。

如果版面只能放两条，保留第一条和第三条。
如果岗位更偏 Go 后端，可把第三条换成“设计租约与Checkpoint，支持任务故障恢复”。

不要把七条全部放入简历。
条目越多，面试官越容易追问到你没有亲自理解或验证的区域。

## 事实边界

- Go 主链、Eino 固定图、SQLite 状态、查询治理、SLS CLI、方舟摘要和离线评测已实现；
- 飞书接收、卡片动作、Reply/Patch 与可靠投递功能已实现，真实平台验收待应用权限；
- 真实阿里云 SLS 与真实火山方舟已通过本地 Web 串入同一次调查；
- 当前真实试点是单主 Logstore 的 count-only 模板；
- SQLite 是单实例技术预览，不等于生产级多机调度；
- 跨 8 个 Logstore、真实 Metrics/Trace、企业 Runbook 和自动变更尚未完成；
- 项目只给出证据和建议，不自动执行重启、回滚或修复。

面试时不要虚构生产 QPS、准确率、节省时长、故障恢复次数或个人独立上线经历。
如果某项不是你实际完成并能复现的工作，就不要用第一人称认领。
